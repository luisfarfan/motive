# Native UI evolution — verification

Verified locally on 2026-11-16–17. Baseline UI: `7280c5c`. Isolated branch `codex/ui-evolution` in `motive-ui`.
H10 was fully verified and merged in main at `0370ca4` during this task; its
three complete commits were incorporated, then consumed by GPUI. No partial
engine changes were copied. All UI-owned changes are outside the engine and
Claude's design directory. This report supersedes the capability limits of the
historical [UI-0–UI-3 checkpoint](ui-native-verification.md).

## Delivered controls

- Modular Studio owner, workspace, scene/source/device views, native forms,
  output/profile/settings panels, H10 presentation and separated editor geometry.
- Named scene creation/rename/removal, Cut/Fade duration and real progress/cancel.
  Camera/window/pattern/overlay addition, reuse, unused-resource release,
  layer visibility/order/transform and exact RGB overlay color.
- Native output-profile create/update/delete, selection, explicit save/restore,
  Auto/VT/x264, CBR bitrate, keyframes and reordering. Actual fixed dimensions/FPS
  are informational, never presented as unimplemented configurable controls.
- Loopback RTMP/RTMPS port configuration, preflight, start, deferred cancellation,
  stop, recovery and real encoder/output counters. Keychain accepts opaque
  references only; secrets remain in the authorized local helper.
- H10 channels keyed by stable input ID, stereo peak/RMS, master, gain faders,
  mute, device add, explicit disconnect/reconnect/remove and mixer save/restore.
  No GPUI audio processing, duplicate mixer or invented meter data.
- Local UI-v1 theme/safe-margin preferences, real diagnostics and last output
  file. Structural deletions/restores, profile overwrite and output stop use
  native confirmations. Forms, confirmations and fader gestures guard revisions.

[Architecture and capability map](ui-architecture.md) describe ownership and
remaining contracts. This is a functional studio increment, not completion of
Motive's entire UI or Design System.

## Failures found and corrected

1. A plain Kit dialog configured callbacks but had no buttons. Added its explicit
   native footer/action/close components; retained `failed-dialog-footer.png`.
2. An open popover covered the confirmation. Close it before opening the dialog;
   `failed-dialog-stacking.png` and `confirmation-fixed-1024.png` preserve both.
3. The initial H10 layout unnecessarily hid the second channel in compact mode.
   Tightened channel rows, added independent scrolling and kept real P/R values;
   `mixer-before-density.png` vs `final-edit-light-1024.png`.
4. Kit 0.10 did not transfer pointer focus to the slider. Left moved the selected
   canvas layer instead. A small focus adapter delegates stepping to the existing
   Kit state; both final gain and unchanged X were verified through MCP.
5. The recovery banner allowed pointer-down to reach the canvas underneath.
   Occluded the banner and stopped that event. `failed-recovery-click-through.png`
   vs `recovery-click-fixed.png` show the correction on the final bundle.

No native engine change, relaxed readiness rule or weakened test assertion was
used to fix these UI defects. The earlier failed artifacts remain local.

Both unchanged real-audio suites passed on the final hash: pilot 25.02 s and
full mixer 90.79 s. `h10-manifest.json`, `h10-pilot.json` and `h10-mixer.json` are

a requested −12 dB. The full test verified input reuse, independent controls,
Cut/Fade with continuous global audio, disconnect/reconnect, ID permutations,
restart/restore, intentional clipping and unchanged project/profile documents.

Both had zero output drops, maximum interior video PTS gaps of 34 ms and audio

One **failed pilot attempt is retained** in `h10-failed-01/`: the spectral
comparison measured −2.27 dB instead of the required −12±1 dB in the microphone

measurement window contained extra energy (RMS 0.0877, peak 0.3953). Its cause was
not isolated. A fresh process with the same binary/script/assertions passed;
no tolerances, engine code or test fixture were changed. This is an unresolved
sensitivity of the physical-mic measurement, not a claimed engine fix.

The last native recording exercised canvas move, aspect-preserving corner

## Reproduction

Use the existing signed bundle workflow. Do not replace a running bundle or run
physical capture concurrently with another worktree. Reserve the shared
`physical-test.lock` with an `OWNER` beginning `UI task:`.

```sh
cargo test --locked
cargo clippy --locked -- -D warnings
cargo fmt --all -- --check
python3 scripts/verify_ui_regressions.py \
  --camera-id '<authorized camera UID>' \
  --microphone-id '<authorized microphone UID>'
# Run each H10 suite from a fresh, idle signed process with no mixer inputs:
python3 scripts/verify_h10_audio.py --microphone-id '<authorized microphone UID>'
python3 scripts/verify_h10_mixer.py --microphone-id '<authorized microphone UID>'
```

The audio pilot plays a controlled local 997 Hz speaker fixture and records the
physical mic with the internal tone; it needs an audible local speaker path.
Neither suite simulates a physical hot-unplug or changes system permissions.

For visual repetition, launch with `MOTIVE_UI_SIZE=1024x780` using the documented
`open -n --env` option; default is 1440×980. Add the native tone/mic, select a
layer, click its fader then Left and query `status`; only gain must change. Mute
both, confirm silence on master; disconnect/reconnect one channel through Audio.
Open profiles, make a shared MCP edit, then attempt to submit the old draft:
reject it, preserve the newer core value. Restore a saved project after restart
and compare the graph/IDs. Follow the historical editor gestures for drag,
resize, snapping, undo/redo and independent portrait layout.

Decode each real output with ffmpeg; use ffprobe for H.264/AAC, dimensions, frame
count and PTS. Preserve a failed report before any clean retry. Screenshots and
recordings stay ignored; only aggregate results and reproducible procedures are
tracked. [Visual QA](../design-qa.md) lists reference/native comparisons.

## Remaining limits

Source/layer/audio-input rename, inactive thumbnails, recording library and
agent proposals lack suitable shared contracts. Secret entry stays in the local
Keychain helper. Public destinations, configurable resolution/FPS, monitoring,
filters, system audio and simultaneous outputs remain unavailable. No fake UI
controls advertise them. See the architecture map for the minimum next contracts.

USB hot-unplug, permission revocation, sleep/wake, long sessions and other macOS
versions remain unverified. Positive RTMPS and the intermittent final VT PTS gap
retain their H8/H9 limits. Native keyboard/AX checks are not a full VoiceOver
certification. Very long fractional transforms may require focusing/scanning
the compact numeric field; their full precision is retained, never rounded away. Preview still copies frames through CPU memory; measurements are
debug-build observations, not a claim of UI optimization or release performance.
